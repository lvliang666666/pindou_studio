## 1. 透明格支持 + 自动抠背景（背景格子不放豆）

**状态**：已完成（v1.6.0，2026-10-28）——透明格支持 + 手动擦成空格；
自动抠背景经多轮实测不稳定，用户决策移除（保留决策痕迹：flood fill +
Sobel 边缘保护 + 去噪三版迭代后仍不可靠）

### 背景

- 拼豆社区标准玩法：图纸背景格子留空（底板露出来），只拼主体图案。
- 当前转换引擎把所有格子都填豆（量化阶段无"空格"语义），透明 PNG
  的 alpha 信息在降采样阶段已保留（预乘 alpha），只差量化与图纸
  数据模型支持"这一格不放豆"。
- 抠掉背景也是「多图拼合放同一块底板」的前置：透明底小图拼到一起
  不会互相垫底色。

### 方案要点

1. **数据模型**：`BeadPattern` 增加空格语义——cells 中空格用特殊标记
   （null 或哨兵 BeadColor），`totalBeads` 只统计非空格；counts 不含空格。
2. **转换引擎**：降采样后 alpha 低于阈值的格子输出为空格；抖动
   （Floyd-Steinberg）时空格不参与误差扩散（不向邻居传播误差、
   不接收误差）。
3. **自动抠背景**：纯色背景自动检测——采样四角/四边像素取主色，
   容差内视为背景置透明；参数区开关 + 容差滑块；手动橡皮擦兜底
   （画笔模式右键擦除已有，扩展为"擦成空格"）。
4. **全链路适配**：画布（空格画底板色/棋盘格）、导出 PNG（空格
   不填色不标色号）、CSV（不计空格）、打印 PDF（空格留白）、
   统计（总豆数/底板数按非空格算）、项目保存/加载（RLE 编码
   空格色号）。

### 影响面

- `lib/core/converter.dart`：BeadPattern 空格语义 + 量化跳过空格
- `lib/core/palette.dart` 或 converter：空格哨兵定义
- `lib/state/editor_state.dart`：抠背景参数（开关+容差）、擦除语义
- `lib/ui/pattern_canvas.dart`：空格绘制
- `lib/ui/export_service.dart` / `lib/ui/print_service.dart`：空格留白
- `lib/data/project_model.dart`：空格 RLE 编码
- 新增 `test/transparent_test.dart`

### 关联

- 批次 B（自定义正方形底板排版）依赖本条目：透明底图拼一板不互垫底色

## 2. 自定义正方形底板排版（一板多图）

**状态**：已否决（v1.6.0~v1.6.3 实现后于 v1.6.4 整体回退，2026-10-31）。
原因：拖动摆放的手势改造连续破坏画笔核心交互（左涂右擦），两轮修复
均引入新问题，用户决策回退。若未来重启此需求，底板显示/分区线等
纯绘制部分可单独实现，避开手势改造。

### 背景

- 拼豆店常见多种标准底板，用户需求：底板为正方形、尺寸自定义、
  最小 50x50（用户明确"底板肯定是正方形 x*x"）。
- 一块底板可放 1 张或多张拼豆图（50x50 放 1 张大图 / 2 张 50x25 /
  4 张 25x25 等），生成"这块板上每格放什么豆"的图纸。
- 现有代码 29x29 硬编码多处：converter.boardCount、
  export_service.splitByBoards、print_service 分板、pattern_canvas
  底板虚线、editor_page 统计行——底板尺寸需参数化为项目级设置。

### 方案要点

1. **底板尺寸参数化**：项目级设置（默认 29 保持兼容），统计/分板/
   打印/画布虚线全部读该设置。
2. **一板多图布局**：复用 BeadStitcher 拼合引擎，新增"固定总尺寸
   （= 底板尺寸）+ 板内布局"模式：N 张图按面积占比分配板内区域，
   pad 到各自区域后合成一张 boardSize x boardSize 图纸。
3. **依赖批次 A**：透明底小图拼到同一块板不互相垫底色。

### 影响面

- `lib/core/converter.dart`：boardCount 读底板尺寸参数
- `lib/core/stitcher.dart`：固定总尺寸布局模式
- `lib/data/project_model.dart`：底板尺寸字段
- `lib/ui/export_service.dart` / `lib/ui/print_service.dart` /
  `lib/ui/pattern_canvas.dart` / `lib/ui/editor/editor_page.dart`：
  底板尺寸参数化
- 新增底板设置 UI（参数区或设置对话框）

## 3. 多图拼合（多张图片合成一张图纸，如四宫格/九宫格挂画）

**状态**：已完成（v1.5.0，2026-10-27）

### 背景

- 用户此前确认的后续方向（优先级仅次于色卡扩展，色卡已在 v1.3.0 完成）。
- 实际拼豆场景常见"多张小图拼成一幅大作品"：四格动漫头像、九宫格风景、
  字母+图案组合。当前只能逐张生成图纸再手工对齐，费时易错。

### 方案要点

1. **拼合引擎**（纯 Dart，可单测）：新增 `lib/core/stitcher.dart`——
   多张图各自按"单张最长边"约束转换（复用 BeadConverter 全参数），
   统一 pad 到目标网格尺寸后按"每行张数"网格拼合，输出一张
   `BeadPattern`（拼合缝不填色，保持各图独立边界）。
2. **编辑器接入**：拼合结果直接装入现有 EditorState（pattern +
   手动编辑/导出/打印/保存全链路复用，零改动）；参数区新增
   「多图拼合」按钮 + 拼合对话框（多选图、单张最长边、每行张数、
   实时预览总尺寸）。
3. **不引入新依赖**：图片解码/转换/导出全部复用现有设施。

### 影响面

- 新增 `lib/core/stitcher.dart`（拼合引擎）
- 新增 `lib/ui/stitch_dialog.dart`（拼合对话框）
- `lib/state/editor_state.dart`：新增 loadPattern 入口（拼合结果装入）
- `lib/ui/editor/editor_page.dart`：参数区新增入口按钮
- 新增 `test/stitcher_test.dart`（拼合引擎测试）

### 关联

- 依赖 v1.4.0 的原图留存基础设施（无直接代码依赖，交互模式一致）

## 4. 图片与豆图仓库管理（导入图片可留存复用，豆图库可视化统一管理）

**状态**：已完成（v1.4.0，2026-10-24）

### 背景

- 导入的原图只存在内存（`EditorState._pixels`），保存项目时不落盘
  （`SavedProject` 仅存 sourceFileName 展示用）。加载旧项目后原图已丢，
  无法调整亮度/对比度/颜色数等参数重新转换——想微调只能重新找图重新导入。
- 打开项目对话框是纯文字列表（图标+名称+尺寸色数），无缩略图预览，
  图纸多了以后靠名字很难认出哪张是哪张。
- 项目列表无删除/重命名/复制入口，误存或废弃项目只能去文件目录手动删 JSON。

### 方案要点

1. **原图随项目留存**：`SavedProject` 增加 `sourceImage` 字段（原图字节，
   PNG/JPEG 原样存储，不重编码）；保存项目时把原图写入
   `sources/<id>.<ext>`（与 JSON 分离，避免 JSON 膨胀），加载项目时恢复
   `_pixels`/`previewImage`，参数调整/重新转换立即可用。旧项目无原图照常打开。
2. **豆图库管理对话框升级**：打开项目对话框改为缩略图网格/列表双视图，
   每项带缩略图（已有 thumbs/<id>.png 基础设施）、名称、尺寸、色数、更新时间；
   每项操作菜单：打开 / 重命名 / 复制 / 删除（删除需确认）。
3. **导入图片历史**：新增 `imports/<id>.<ext>` 目录，导入图片时自动留存副本；
   参数区「导入图片」按钮旁加「最近导入」下拉，一键重选最近用过的图。

### 影响面

- `lib/data/project_model.dart`：SavedProject 增加 sourceImage 相关字段（扩展名/尺寸）
- `lib/data/project_repository.dart`：sources/imports 目录管理、原图存取 API、
  项目复制/重命名 API（连带缩略图与原图文件）
- `lib/state/editor_state.dart`：save 时写原图、loadProject 时恢复原图
- `lib/ui/editor/editor_page.dart`：打开项目对话框改造（缩略图+操作菜单）、
  导入区「最近导入」入口
- `test/project_test.dart`：原图留存/恢复、复制/重命名/删除联动测试

### 关联

- 依赖现有 thumbs/ 缩略图基础设施（已具备）
- 「多图拼合」（用户已确认的后续方向）以本条目的图片留存为基础，
  建议先做本条目
